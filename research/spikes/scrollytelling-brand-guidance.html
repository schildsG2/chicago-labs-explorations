Brand Guidance

Staying On-Brand in Scrollytelling

Sep 18, 2026 — consulted the g2-brand-creator skill for guidance, not a rendered artifact

1. Executive Summary

This is guidance, distilled from G2's brand-creator skill (color/type tokens, voice rules, and a documented list of web anti-patterns), on how to stay recognizably G2 while building the PPL Scrollytelling epic — and applied specifically to scrollytelling's own techniques (scroll-triggered reveal, sticky visuals, section transitions, card composition) rather than restated generically.

One tension to flag up front: the brand-creator skill is tuned for marketing collateral (landing pages, decks, PDFs) and its token set differs from Elevate — most notably it specifies body/heading text as pure black #111, while Elevate (already governing every prototype in this repo, per the root CLAUDE.md) specifies text-default #201f23 and explicitly forbids pure black. This epic is a product UI experience built on Elevate, not a marketing page — Elevate's token wins. Everywhere else (voice, motion restraint, anti-patterns, color hierarchy), the two systems agree and the guidance below applies directly.

2. Color & type — rules translated for scrollytelling

Brand rule (source) Applied to a scrollytelling beat
Default palette is 3–4 colors max: Rorange, Purple, Yellow, white — don't reach for the full brand palette in one deliverable. Don't let every scroll section introduce a new accent color. Purple stays the primary "action/emphasis" color (this already matches Elevate's own "purple for primary CTAs" rule) — Rorange is reserved for true brand-identity moments, never for data or sentiment (also already an Elevate rule — the two systems agree here).
Figtree only, no exceptions, no fallbacks — applies to every element including charts and data tables. Already Elevate's rule. Extend it explicitly to any custom chart/meter built for the match-confidence visualization (techniques spike §4) — no default system-ui fallback creeping in on a canvas/SVG chart.
Text color is black #111 on light backgrounds (brand-creator token). Superseded here by Elevate's text-default #201f23 — see §1. Don't "fix" copy toward pure black if a future brand audit flags it; this product surface intentionally follows Elevate.
No gradient or animated backgrounds. No dot/grid/noise-pattern backgrounds. No glassmorphism / backdrop-filter: blur(). No CSS/SVG blurred-blob shapes. This directly confirms and sharpens what the earlier techniques spike already flagged as off-brand: illoca's sketchbook/graph-paper texture, goats' and the Pudding piece's gradient backgrounds. Now with an explicit source: no persistent background texture or gradient of any kind, animated or not.
All buttons are pills (border-radius: 100px). Primary button = Purple. Rorange buttons only on dark/navy/purple backgrounds. Applies to any CTA embedded in a scroll beat — e.g. the "still want to talk to a human?" escape hatch the content handoff (§6) already calls out as a ready-made component. Keep it a purple pill on a light section; only go Rorange if that CTA sits on a dark/purple full-bleed section.
One eyebrow standard: 14px/700/uppercase/0.12em letter-spacing, color matches the heading (never a brand color as eyebrow text). No eyebrows unless present in source copy — don't invent decorative labels. If a chapter/step label is added to a scroll section (the "numbered step badge" or "sticky chapter-nav" mechanics from the techniques spike), style it as this one eyebrow standard — not a new ad hoc treatment per exploration, and not colored Rorange/purple text.

3. Voice & copy — rules translated for scrollytelling

Brand voice rule Applied to a scrollytelling beat
The customer is the hero; G2 is the sidekick with the goods. The buyer's own wizard answers should read as the protagonist of the narrative ("you told us...") — not the recommendation engine narrating at them. This is the brand-voice justification for the "attributed quote card" mechanic already in the techniques spike's toolkit (§4), not just a UX nicety.
Data storytelling: pair every claim with proof; turn numbers into meaning, don't just drop them. The match/confidence meter (techniques spike §4) must always pair with the "why" sentence — never show a bare percentage. This is now a voice rule as much as a data-vis one.
Rhythm: short sentences next to longer ones; fragments are fine. Directly usable in the "personalization sentence with one highlighted clause" pattern already recommended (e.g. "Because you need things to work together, we weighted integration support heavily.") — keep it one beat, not a paragraph.
Avoid buzzwords: leverage, unlock, seamlessly, robust, elevate, streamline, best-in-class, cutting-edge, game-changing, etc. Watch for these specifically in auto-drafted "why we recommended this" copy — "seamlessly integrates" and "robust reporting" are exactly the phrasing this kind of generated personalization copy reaches for by default.
Strip "feels very Claude" AI phrasing tics: em-dash-and-restate rhythm, rule-of-three padding ("faster, smarter, more efficient"), hedging throat-clears, hollow openers/closers. This epic's copy will likely be AI-drafted — treat this as a mandatory pass on any generated narrative beat, not optional polish. Read every beat aloud before it ships.
Be authoritative, not hedging ("may," "might," "could help"). The recommendation narrative should make a clear claim — "Because you need X, we recommend Y" — not "this might be a good fit for you." Ties directly to the content handoff's note that confidence scoring doesn't exist yet: the copy should still commit to a clear voice even while the underlying number is a placeholder.

4. Motion & composition — on-brand vs. off-brand, specifically for us

On-brand: scroll-triggered reveal that has a function — content appearing, a value updating, a step advancing. This matches both the earlier techniques spike's "every animation needs a function" rule and the brand skill's own line: animation on background decoration is banned, animation as content delivery is not addressed by that rule and stays governed by the earlier spike's standard.
  • Off-brand, confirmed: animated or gradient backgrounds, blurred blob shapes, glassmorphism/backdrop-blur, dot/grid/noise-pattern backgrounds — this directly rules out several of the very techniques admired in the earlier site audit (illoca's texture, goats'/Pudding's gradients) at the CSS level, not just as a style preference.
  • Cards: hairline outline only (box-shadow: 0 0 0 1px #e8e8e8), no heavy drop shadows, no colored left-border accent stripes, no decorative <hr> or colored divider bars inside a card. Applies directly to the "card-based product reveal" and "attributed quote card" mechanics — build them as flat hairline cards, not the drop-shadow "sticker" look borrowed from the Pudding example (which was already flagged off-brand aesthetically in the techniques spike).
  • Section transitions: use background-color changes and vertical padding, not a literal divider line. Validates the "section tone inversion" toolkit entry (light → purple-tinted, or light → dark) — just without a rule/hr marking the seam.
  • Icons: black or white only, no colored background container/box around them. Relevant if step/chapter badges use an icon instead of a plain numeral.

5. Easy to violate in a scrollytelling context specifically

  • Overusing Rorange for "match found!" moments. A recommendation reveal is an emotionally charged beat, and Rorange is a natural instinct for "this is the moment" — but Rorange is brand-identity only, never a data-positive or sentiment color. Use Purple or Elevate's semantic tokens for that emphasis instead.
  • Motion that reads as "AI slop." Stacking too many animated reveals back-to-back turns a story into a tech demo. Test every animated beat against: would removing it lose information? If not, cut it.
  • Breaking calm density with too many stacked beats. The brand skill's own copy-density rule ("2–3 sentences max" per slide) translates directly: no single scroll beat should carry more than ~2–3 sentences.
  • Buzzword creep in generated "why we recommended this" copy — see §3's buzzword list. Easiest to catch by reading each beat aloud before shipping it.
  • Inventing a new eyebrow/label style per exploration. Multiple explorations will be built over time (§ Variant One is just the first) — each one reaching for its own chapter-label treatment instead of the one eyebrow standard (§2) will drift the epic visually inconsistent with itself, let alone with G2.
